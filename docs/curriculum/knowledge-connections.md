# 知識を結び付ける学習メニューの設計案

確認日：2026-10-24。状態：`draft`。社会・理科を横断する教材の編集案。アプリ実装・取込は未実施で、公式の必修範囲を追加しない。数学の実装・作問は保留。

## 1. 「関連がある」を学べる関係にする

「何を使って、何を説明するか」を示す。熱で機関を説明できても産業化の原因は説明し切れない。資源・資金・労働・技能・制度・市場・貿易・地域条件も検討し、発見・実用化・普及・社会変化を区別する。

| 関係 | 矢印の意味 | 記録すべき限界 |
|---|---|---|
| 前提 | 基礎となる理解 → それを使う理解 | 編集上の学習支援。学校の正式な履修順とは別 |
| 仕組み | 概念・モデル → 説明する現象・装置 | 適用条件、説明できない部分。後世の説明を発明当時の知識と混同しない |
| 背景 | 資源・制度・人間活動 → 検討する出来事・利用 | 成立条件の候補。必要条件・十分条件と断定しない |
| 影響 | 歴史的出来事 → 変化した出来事 | 時間順だけで因果としない。経路・他の要因・地域差を要検証 |
| 比較 | 比較元 ↔ 比較先 | 共通の比較軸と相違。類似を同一性や因果に読み替えない |
| 証拠 | 観察・出来事の資料 → 支える限定的な主張 | 資料の作成者・時期・条件・欠落。一般化できる範囲 |

「範囲確認」は公式範囲との対応、「資料確認」は限定的事実、「編集案」は学習上の接続、「仮案」は追加検証待ち。単一の信頼度にまとめず、事例の存在・作用の経路・社会全体への寄与を分ける。

## 2. ノードを混同しない

**単元ノード**は既存の `unitId`・履修条件・小目標を参照し、出来事とは区別する。

**出来事ノード**は `eventId` を新設する案。E1〜E5は略記で、登録済みIDではない。期間・場所・関係者・確認事実・未確認事項・資料を記録する。

| 略記・提案ID | 対象と根拠・状態 |
|---|---|
| E1 `EVT-STEAM-LONDON-1797` | 1797年ロンドンの化学工場の回転式蒸気機関。来歴はH1で確認。英国全体の普及率は不明 |
| E2 `EVT-INDUSTRIAL-GB-18C19C` | 18〜19世紀英国の産業化。歴史総合へ接続する編集上のまとまり。地域・産業・期間は教材で絞る |
| E3 `EVT-INDUCTION-LONDON-1831` | 1831年8月29日、ロンドンの Faraday の誘導環。装置と短時間の誘導電流の記述をH2で確認 |
| E4 `EVT-ANTHRAX-GERMANY-1876` | 1876年ドイツの Koch の炭疽研究。H3の解説で確認。原論文の照合は次段階 |
| E5 `EVT-HYGIENE-FRANCE-L19C` | 19世紀後半フランスの衛生実践を調べる仮ノード。H3は先行実践も説明。病院・自治体・制度・時期は未確定 |

原史料・標本・装置は `sourceRefs` / `assetRefs` で管理する。

## 4. 迷わず戻れる学習メニュー

入口は問いのカードとする。「蒸気機関だけで産業革命を説明できる？」「誘導電流から電気が届くまで何が必要？」「微生物の理解は暮らしをどう変えた？」の3経路を提案する。

問い→基礎→資料1点→関係1本→振り返りの順。出発した問い・現在位置・直前へ戻る操作と「元の問いへ戻る」を保つ。地図は次の候補2〜3件に関係名と進む理由を示す。訪問順と履修順は別。

未履修でもロックせず「基礎から」「資料を読む」「深掘り」を選べる案とする。選択科目の未履修を遅れと表示しない。「科学と人間生活」の微生物は科目内選択なので中学への代替入口を用意。管理IDを画面の主見出しにしない。

閲覧・読了・説明できる状態を分ける。根拠選択、強すぎる因果の修正、別事例への適用を `objectiveId` ごとに確認。読了や一度の正答で単元全体・他科目を習得扱いにしない。

## 5. 原稿管理への追加案

[制作設計](authoring-plan.md)の共通項目を維持し、別の関係原稿に `connectionId`、`from` / `to`（型＋ID）、`relationType`、主張、時代・地域、複数要因、根拠の強さ・限界、追加調査、戻り先を記録する案。比較は双方向、それ以外は主張ごとの方向を保存する。

`prerequisiteUnitIds` は学習上の前提のみ。影響・背景・比較や正式な履修条件と混ぜない。資料確認と教材の `review` 状態も別。追加項目を現行の四択取込形式へ直接送らない。

次は地域・事例確定→史料追加→歴史因果と理科説明の確認→小目標・問い→独立レビュー。図の出典・利用条件は `assetRefs` に記録する。
