# 新規アップロードの一時処理（次の別変更）

2026-10-24。設計・実装範囲を確定した文書です。**まだ実装・公開していません。既存原本の移動や削除は行いません。**

現在はアップロード原本をDriveへ、OCR全文をSheetsの `source.analysis` へ保存し、試作・承認・まとめ作成・再依頼で再利用しています。処理後にファイルだけ削除すると、その後の作問が壊れ、OCRも残ります。新規資料に限り期限付きセッションへ切り替えます。

## 対象と流れ

1. owner・状態・期限を持つ一時セッションを発行し、試作→承認待ち→まとめ作成を一つの論理作業として扱います。最初のアップロードから最大1時間を初期案とし、承認待ち・再試行で延長しません。実測検証前に「1時間以内に必ず削除」と公開表示しません。
2. 原本・OCR・生の会話入力をセッション専用一時領域に置きます。恒久教材一覧、Sheetsイベント、アクセスログ、例外、Workflowの引数・戻り値・履歴へ本文を入れません。WorkflowへはIDだけ渡します。
3. 試作と承認後の作成は同じ有効セッションを参照します。初期上限は10ファイル・50問程度で検証し、有料処理の開始前と返却後に期限・取消を照合します。
4. 完了・失敗・取消・期限切れで一時データを清掃します。独立した清掃処理がクラッシュによる取り残しを再確認し、実体の消失確認後だけ削除済みにします。
5. 保持するのは生成した問題・学習記録と、本文を含まない最小限の出典receiptです。原本の再表示や期限後のOCR編集は提供しません。再利用時はアップロードし直します。

## 変更箇所

- upload-token / upload-completeと `uploadSources`: 新規資料を一時セッションへ紐付け、失効後の遅延アップロードも拒否する経路に変更。従来のDrive直接アップロード許可をそのまま再利用しません。
- `analyzePlanningSource` / `analyzeSource`: `source.analysis` へ全文を書かず一時領域へ保存。
- `buildPlanningContext` / `sourcesFromState`: owner・session・期限を検証して取得。
- request / retry: 有効セッションだけ再利用。既存教材の旧経路は互換維持。
- Planning / SourceReadingEditor / SourceMaterialPanel: 一時資料の期限・処理後削除を説明し、削除済みプレビューを作りません。
- planning messages: 生の会話やAIによる本文の大量転載も恒久保存へ流れないよう分離。問題だけからの派生は原本未確認と明示。

## 必須検証

- 他人のsessionを取得・更新・再開できない。
- 期限・取消後にアップロード、paid call、結果の公開を進められない。
- 成功・失敗・取消・期限・クラッシュ後に清掃され、遅延アップロードで復活しない。
- 検査用の原本/OCR文字列が永続ログ・Workflow履歴・例外に残らない。
- 既存の教材・問題・学習記録が変更・削除されない。
- 生成問題に長い本文をそのまま残す経路を検出する。

原本を削除しても、LLM提供者側の保存期間や入力権限の問題が自動的に解消するわけではありません。利用条件とprovider側の扱いは別に確認します。
