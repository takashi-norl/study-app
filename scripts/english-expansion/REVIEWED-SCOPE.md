# Reviewed five-word author/editor scope

This reusable runner separates a new exact five-word scope from the frozen 20-item prototype. Each authority binds its own scope ID, five independently approved seeds, author work ID/hash, fixed editor policy/ID, all code and evidence, legacy store/ledger, existing private approvals and native scale hold. It does not change the old pilot capacity or enable its runtime.

Current synchronous ceiling is $0.018 for Haiku 5.5 author (medium, thinking disabled, 16,000 output), plus $0.300 for Sonnet 5.5 editor (high, 20,000 output). These are worst-case reservations under the existing $500 / conservative ¥100,000 project guard, not an additional budget or expected bill. Output usage includes reasoning exactly once. Author input is counted at at most 50k and reserves the entire 100k pricing tier; editor input counts at most 25k and reserves 50k. Existing historical allowances, cash obligations, pending outcomes and paid raw results remain part of the fresh guard.

The default CLI operation is dry-run. Only the root operator creates an approved `scopeAuthoritySchema` document after the current offline work settles. `scopeAuthorWork` builds the exact work from `selectedScopeSeeds` and `selectionNotes`. No credentials are required for dry-run. Supply `--out`, `--base`, `--runtime`, `--authority`, `--selection`, `--work`; `--send` is the explicit paid operation. The selection is evidence, never execution authority.

After author output is saved and priced, `scopeEditorWork` is built from its exact parsed units and alternatives notes, with the author request ID and complete raw-envelope SHA. Root inspects that work before invoking the same runner. The Sonnet editor inspects every complete card but returns only exact-source-hash verdict records and necessary before/after patches. The patch allowlist permits meaning/POS, examples and tests, preserving seed identities, aliases, levels, tags and source provenance. Every card retains three examples and four modes. Useful exact-blank contextual alternatives are required unless a specific, independently reviewable reason explains their absence.

Neither response means completion. The runner saves immutable author/editor results and complete reconstructed drafts, with no private approval, audio or publication. A separate native reviewer must read all reconstructed final cards and issue `scopeNativeReviewSchema`; root then signs `scopeFinalApprovalSchema` binding the review, editor result and current settled ledger. `finalizeReviewedScope` defaults to dry-run unless `write:true`; it rechecks source/raw/cost/seed/draft evidence and preserves an immutable intent before using the existing private publisher. It can resume a partial write with the identical result, but cannot replace a different approved revision. The native scale hold and public catalog remain unchanged.

Any submitted request without durable raw evidence keeps its worst-case reservation and cannot be resent. A saved truncated or malformed result is charged and retained; it is never silently regenerated. Internal validation failures produce a bounded diagnostic message, while underlying provider errors remain sanitized. There are exactly two paid request identities in a scope; no automatic retry or repair request exists.

For a later batch rollout, reuse the selected-seed/source contracts, author/editor policy, deterministic patch application, scoped registration and final review evidence. A separately reviewed Batch adapter must reserve all outstanding discounted liabilities under the same lock before sending; this runner does not authorize Batch use or concurrent scopes.
