# English expansion: offline planning only

This directory has no API client, secret access, paid call, worker hook or UI integration. It does not alter the active 7,500-word pipeline. Run the tests with:

```sh
node --test scripts/english-expansion/*.test.mjs
```

`allocation.mjs` defines 20,000 total canonical units: 7,500 core plus 12,500 net new units (8,500 words and 4,000 phrases). Six primary collection targets total exactly 12,500; genre subtotals are part of the allocation, not extra assets. Eiken relevance and CEFR are estimates, not an official list. A low-quality or duplicate candidate cannot be counted just to meet a target. The first expansion pilot is at most 20 units; later waves are capped at 1,000.

## Interfaces

- `schema.mjs`: `validateSeed`, `validateUnit`, `validateRelations`, `approveUnit`, stable `unitIdFor` / `senseIdFor` and `hashContent`. A canonical word/phrase contains subordinate senses, each with English/Japanese meaning, three original bilingual situational examples and four authored four-choice tests. Word mode means “choose the expression” for phrases. All choices have Japanese meaning and feedback. Alternatives must be contextual, not unconditional synonym claims. Independent hash-bound review is mandatory before publication or audio.
- `registry.mjs`: `createRegistry({ approvedBatches, frozenEntries, ownInventory })`, `classifyCandidates`, `countDistinct`. Approved base files and frozen snapshots are hash-checked. Aliases/verb forms participate in overlap detection. A homograph/alias collision is held for explicit semantic review; it is never silently counted as a new unit. Extra genres, examples, voices and senses do not increase the canonical unit count.
- `budget.mjs`: `assessSharedBudget` and immutable `reserveExpansionRequest`. The USD 500 ceiling includes phase-one text actuals plus pending reservations, **all** phase-one audio reservations (including the explicit quota retry), and expansion actuals/pending reservations. Existing phase-one caps remain USD 100 text / USD 400 audio. Unknown outcomes retain the full reservation and block new work. Replay of a known request returns a reuse/reconciliation action, never another paid-send authorization. Completed zero-cost outcomes must still have an authoritative saved response.
- `loaders.mjs`: read-only loading of the existing private output; missing base accounting files fail closed. Creation of an empty expansion ledger requires `allowNewExpansion: true`. The loader does not write that ledger.
- `planner.mjs`: `planningStatus` reports registered and approved counts separately. `planWave` admits only new accepted IDs in 1–5-unit request groups and returns a bounded prefix with enough budget. It refuses expansion until the distinct approved/frozen base reaches 7,500. The caller supplies a **worst-case token-priced ceiling**, not an average cost estimate. Returned reservations are plans and do not send requests.

`audio-adapter.mjs` reads the real `audio/reservations/<cacheKey>.json`, `audio/retry-reservations/<cacheKey>.json` and `audio/assets/<cacheKey>/` layout. Each normalized reservation includes `requestId`, `reservedMicroUsd` and `outcome` (`ready`, `known-quota-rejection`, `reserved-not-sent`, or `uncertain`). A started request without complete outcome metadata is uncertain; the entire reservation remains counted and blocks spending. Explicit retries verify the archived rejection hashes and their own `started.json`. An original quota rejection and its retry remain two counted reservations. Missing accounting directories fail closed.

Cash top-ups are prepaid funding, not a second usage charge. Each `cashPurchases` record must include its provider and funding pool, for example `{id:'eleven-topup-1', provider:'elevenlabs', fundingPool:'audio', amountUsdPreTax:100}`. Other supported funding is `provider:'anthropic', fundingPool:'text'`. Unknown/mismatched pools fail closed. Track actual `chargedJpy` when available.

The overall liability is `max(text usage/reservations, text cash obligations) + max(audio usage/reservations, audio cash obligations)`. This covers unspent prepaid funds without counting their consumed credit twice. For example, text costs USD 300, audio usage USD 100 and audio top-ups USD 400 create USD 700 of liabilities, so the guard stops; two independent USD 400 comparisons would be wrong. Both the USD 500 guard and the combined all-in yen guard apply.

The user cap remains JPY 100,000; USD 500 at the conservative planning rate of JPY 180/USD plus a 10% allowance is JPY 99,000. These are planning assumptions, not a live exchange-rate/tax quote. Observed `chargedJpy` above the assumed conversion/tax guard stops work for review. `reserveCashTopUp` returns a separate durable cash-obligation plan and never purchases anything or adds a usage call. Actual checkout amounts need tracking; automatic top-ups are not authorized.

## Still required before an unattended paid expansion

1. Complete/reconcile the base, including words held at the repair limit. Preserve every existing asset and billable request receipt.
2. Add durable phase-two inventory/manifest/ledger storage, immutable raw provider responses and review receipts. Freeze the base catalog hash and maintain canonical alias/sense indexes. Link existing units instead of reauthoring them to fill quotas.
3. Stop and fully drain phase one, then add an **exclusive shared lock** around fresh base accounting reads, reservation persistence and dispatch. The active base worker does not use an expansion lock: concurrent paid expansion is forbidden even if a snapshot includes its pending reservations. The module requires explicit `lifecycle: {phaseOneStopped: true, phaseOneSettled: true, exclusiveSharedLockHeld: true}` and verifies no base text/audio reservation remains unsettled. A future dispatcher must obtain these facts from real process/lock checks; a heartbeat must not simply set the flags. Base work must stay stopped until its spending authority is integrated with the shared gate.
4. Build original-content prompts and schema-output generation in batches of 1–5 units; separately review language, one defensible answer, source/register accuracy, regional/current slang and audience notes. Do not copy film scripts or claim every fictional expression is authentic slang. Preserve complete raw results before decoding; do not automatically retry unknown outcomes.
5. Price the actual model and count input tokens before every paid request; reserve the bounded output budget and independent review together. Persist “sent” before the network call, then reconcile provider usage. A batch submission needs immutable submission identity and confirmed provider batch ID before another wave is allowed.
6. Run the 20-unit text-only pilot, review all outputs independently, and recompute cost per approved unit. The 20,000 target is conditional on the JPY 100,000 total cap; the planner does not imply it is funded. Defer expansion audio until a separate reservation fits the same total.
7. Add app/catalog adapters for phrases, multiple senses and register/audience display; resolve all relation targets with `validateRelations`. Existing four-grade app types cannot consume this format unchanged. Export only approved units; report registered, approved and audio-ready counts separately.
8. Wire the hourly monitor to durable status only after the dispatcher exists. Notify for completion, cap/credit exhaustion, held quality outcomes or required action. A missing file, paused worker or unchanged status must not trigger automatic purchases/restarts.
