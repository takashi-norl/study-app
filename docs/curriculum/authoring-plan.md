# 社会・理科の教材・問題 制作設計

作成日：2026-10-24。対象範囲は[総覧](README.md)と教科別の4ファイル。以下の制作順、問題数、データ項目はアプリ向けの提案であり、文科省の指定ではありません。

## 1. 最初に作る教材

まず「短い説明＋読み取る資料＋基礎・解釈・理由の3問」を4系統で試します。[試作原稿](pilot-lessons.md)を用意し、別のAI担当が解き直して独立確認しました。正答率の実測や教員による内容確認はまだ行っていません。

| 優先 | 制作対象 | ねらい・完了条件 |
| --- | --- | --- |
| P0・今回 | 全分野・科目の範囲表、公式出典、履修条件、4教材12問の試作 | 対象単元と出典をたどれ、必修・選択・学年モデルを混同しない |
| P1 | 中学社会・理科の全学年を1単元ずつ小規模制作 | 各学年×2教科の代表教材をそろえ、語彙・難度・資料の長さを点検する |
| P2 | 中学の各分野と、高校の地理総合・歴史総合・公共、理科の基礎4科目・科学と人間生活 | 全員に必要な内容と履修経路別の内容を先に整備する。理科5科目を全員に要求しない |
| P3 | 高校の探究・倫理・政治経済、物理・化学・生物・地学 | 基礎→発展の前提関係、複数資料・複数段階の推論を整える |
| P4 | 教科横断の探究、教科書別配当、試験別演習 | 学校・教科書・対象試験を指定してから範囲を確認する |

P1以降の制作数・費用・開始日は未確定です。既存の英語教材の予算枠を社会・理科に転用する前提にはしません。

## 2. 学習目標の粒度

範囲表の単元は制作管理のまとまりです。例えば「電流」なら「電流計を正しく接続できる」「グラフから抵抗を求められる」「測定値がモデルからずれる理由を考えられる」を分けます。同じ単元で用語を言い換えただけの問題を量産せず、1問が何を確かめるかを明示します。

| 目標の種類 | 社会の例 | 理科の例 | 確認方法 |
| --- | --- | --- | --- |
| 知識・概念 | 主権と権力分立を区別する | 質量と密度を区別する | 用語確認、事例分類 |
| 技能・資料読解 | 年代・地域・資料作成者を確認する | 変数・単位・測定条件を確認する | 表・図・史料・グラフの読み取り |
| 思考・判断・表現 | 複数の立場と根拠から説明する | 結果からモデルを選び限界を述べる | 根拠選択、短答、論述、ルーブリック |
| 探究と振り返り | 問い・調査方法・結論を見直す | 仮説・条件制御・再現性を見直す | 探究ノート、自己点検、対話や実活動 |

難度は当面 `foundation`（基本確認）、`standard`（資料の解釈・適用）、`extension`（複数条件・比較・説明）とします。公式の難度区分ではありません。態度を回答速度・連続正解数だけで判定しません。

## 3. 教材原稿の仕様

この表は今後の原稿管理用の共通案です。現行アプリの入力項目と同一ではありません。教科別資料に示したメタデータ名・表記は用途を説明する例で、実際に原稿を構造化するときはこの表の名前へ統一します。

| 項目 | 記録内容 |
| --- | --- |
| `curriculumVersion` | `mext-jh-2017` / `mext-hs-2018` と確認日。解説の版は出典側で別管理 |
| `unitId` / `objectiveId` | 範囲表の単元ID、単元内の小目標ID。後から名称を変えてもIDは維持 |
| `schoolStage` / `course` | 中学／高校と正式な分野・科目名 |
| `gradeBand` / `gradeBasis` | 想定学年と `official` / `editorial-example` / `school-dependent` の区別 |
| `requirement` | 中学共通、高校全員必履修、選択経路、選択科目、科目内選択を区別 |
| `prerequisiteUnitIds` | 既習が必要な単元。高校の履修科目順は別に保つ |
| `objective` / `assessmentFocus` | 「資料から〜を説明できる」など観察可能な目標と測る能力 |
| `lesson` | 導入→概念→具体例→資料・活動→まとめ。前提・適用条件も説明 |
| `misconceptions` | 典型誤解と、それを修正する説明 |
| `sourceRefs` | 出典ID・URL・章節・確認日。図表の出典や統計年は別に記録 |
| `assetRefs` | 図・地図・表・写真の位置、代替テキスト、利用条件 |
| `questions` | 問題ID・設問・選択肢・正解・解説・誤答理由・学習ポイント |
| `review` | 状態、確認者、対象版、指摘・修正・再確認の履歴 |

状態は `outline → draft → content-reviewed → import-ready` を提案します。範囲表の作成済み、問題の作成済み、内容確認済み、取込済み、公開済みを別々に数えます。本資料の試作は `draft` です。

## 4. 1単元の制作手順

1. **範囲確定**：本文・解説の内容と取扱いを読み、必須事項・例示・発展を分ける。
2. **小目標と前提**：到達目標を分割し、必要な既習事項を確認する。
3. **教材執筆**：オリジナルの説明と例を作る。架空データは「学習用の仮想データ」と表示する。
4. **3問の試作**：基礎、資料解釈、理由・誤概念の確認を各1問。問題文だけで解答に必要な条件がそろうようにする。
5. **独立確認**：作成者と別の確認者が、根拠・唯一解・誤答・難度・履修範囲を検証する。AIによる確認だけの場合は人の確認済みと表示しない。
6. **単元セットへ拡張**：最初は10問程度を目安に、目標の漏れがあれば調整。たとえば知識3、資料解釈4、適用・理由3。問題数で網羅性を代用しない。
7. **取込準備**：教材原稿を確定し、現行アプリに対応する形式へ変換する。図を必要とする問題は表示確認まで行う。

教材テンプレート：

```markdown
# 教材タイトル
- unitId / objectiveId:
- 学年の扱い・科目・履修条件:
- 目標:
- 前提知識:
- 出典（本文・解説の章節）:
- 状態: draft

## なぜ学ぶか
身近な問いを1つ。
## 概念と具体例
定義・関係・条件を説明。
## 資料を読む／観察・実験を考える
出典、測定条件、単位、仮想データの表示。
## 練習問題
3問。設問、4選択肢、正解、解説、各誤答の理由、学習ポイント。
## 振り返り
根拠を説明する問いと自己確認用の観点。
## 確認記録
確認者、確認した版、指摘、修正結果。
```

## 5. 作問時の教科別ルール

### 社会

- 地理では地域名暗記だけにせず、分布・場所・人間と環境・地域間関係を読み取らせる。統計には単位・年・母集団を付ける。
- 歴史では出来事の前後、変化と継続、因果、同時代の地域関係を扱う。史料の事実、作成者の主張、学習者の推論を区別する。
- 公民では制度の説明と価値判断を区別する。政策への賛否それ自体を唯一の正解にせず、提示した条件・資料に照らした妥当性を問う。
- 実在の史料を要約したときは要約と明記し、創作した文を原史料の引用として出さない。

### 理科

- 問題には温度・圧力・装置・系の範囲・単位など必要条件を明示する。計算過程、丸め方、物理的に妥当な値かを確認する。
- 実験では独立変数・従属変数・統制条件・対照・反復・測定誤差を扱う。観測結果と、その結果の解釈を区別する。
- 図の向きや縮尺に依存する問題は、図を実際に添付して確認する。文面だけで図がある前提にしない。
- 危険な薬品・火気・高電圧などの実験は、適切な設備・指導下の活動として扱う。自宅での実施手順としない。
- 科学モデルの適用範囲を明記する。「密度だけで物質を必ず同定できる」「相関があれば原因である」などの断定を避ける。

## 6. 現行アプリへの対応

確認した形式：[問題集取込の形式](https://github.com/takashi-norl/study-app/blob/4bc126c0ec05f76faf5256400fd697f53e0f04b6/src/lib/question-set-import.ts)、[取込時の確認処理](https://github.com/takashi-norl/study-app/blob/4bc126c0ec05f76faf5256400fd697f53e0f04b6/src/server/question-set-import.ts)。確認基準のコミットは[出典一覧](sources.md)参照。

| 原稿側 | 現行取込形式・対応 |
| --- | --- |
| 問題集の識別 | `version: 1`、UUID形式の `bundleId`、`title`、`subject`、`description` |
| 設問と選択肢 | `prompt` 最大3000文字、`choices` は重複しない4個・各最大600文字 |
| 正解 | `correctIndex` は0〜3。選択肢を並べ替えたら正解番号も更新 |
| 解説 | `explanation` 最大3000文字。正解の理由と各誤答の理由をまとめる |
| 学習目標 | `learningPoint` 最大600文字 |
| 出典 | `sourceNote` 最大2000文字に公式URL・章節・単元ID・教材データの出典を記載 |
| 教材への紐付け | `sourceIds` はアプリに登録された教材のUUID。文科省URLや単元IDを入れない。登録資料がなければ空配列とする |
| 学年・単元ID・難度・レビュー | 専用の取込フィールドはない。原稿側で保持し、必要な情報を `description` / `sourceNote` に記録する |
| 自由記述・探究活動 | 現行取込は四択。教材原稿の振り返りとして保持し、自動採点できるとは扱わない |
| 図・地図・表 | 専用の画像フィールドはない。図の表示方法や教材参照をアプリ担当と確認する。試作の小表はテキストでも理解できる形で設問中に再掲 |

1問題集は1〜100問、リクエスト上限は120KiBです。問題文の重複や正規化後に同一になる選択肢は拒否されます。厳密な入力形式のため、`unitId` など未知の項目を直接追加して送らず、変換時に分離してください。`questionTemplate` の既存値は古文単語専用で、社会・理科には設定しません。

取込操作には `reviewed: true` が必要で、問題は運営者本人の確認済み問題集として保存されます。このため、原稿ができたことだけを理由に取込済み・確認済みへ進めないでください。一般利用者向けの共通教材配信とは別の工程です。

## 7. 作問依頼テンプレート

```text
対象の unitId と小目標を1つ指定する。
入力として、対象単元、公式本文・解説の該当箇所、対象学年の扱い、履修済み範囲、
既存問題一覧を与える。

教材の短い説明と、基礎確認・資料解釈・理由判断の四択問題を各1問作る。
必ず、学習目標、設問、4選択肢、唯一の正解、解説、全誤答の理由、学習ポイント、
出典の章節、前提条件を付ける。数値は検算する。
公式資料にない学年指定や、存在しない引用・統計・図を作らない。
架空データは架空と表示する。必要な資料が足りなければ不足を明記して止める。
内容確認前の出力は draft とし、既存問題の表面的な言い換えで数を増やさない。
```

確認者には正解を先に信じさせず、設問から解き直してもらいます。正解が複数成立する、必要な条件が足りない、範囲外の前提が必要、といった問題は差し戻します。
